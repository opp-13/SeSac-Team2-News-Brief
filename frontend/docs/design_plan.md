# AI 뉴스 큐레이션 서비스 — 디자인 브리프

> Figma AI 참조용 문서. 이 문서의 값은 그대로 쓰고, 임의로 바꾸지 마세요.
> `[확정]`은 근거와 함께 결정된 값입니다. `[제안]`은 아직 팀 합의 전이며 조정 가능합니다.

---

## 0. 제품 한 줄 정의

외부 뉴스를 수집해 **LLM이 요약**하고, 사용자의 관심 태그에 맞춰 개인화 피드로 제공하는 웹 서비스.
(번역 기능은 담당자 부재로 이번 디자인 범위에서 제외합니다.)

**주인공은 텍스트입니다.** 이미지·차트·장식이 아니라 기사 헤드라인과 AI 요약문이 화면의 중심입니다. 모든 디자인 결정은 "이게 읽기를 방해하는가"를 기준으로 판단하세요.

**타깃**: 뉴스를 빠르게 훑고 싶은 20~40대. 데스크톱과 모바일 사용 비중이 비슷합니다.

---

## 1. 디자인 원칙

1. **조용한 배경, 선명한 텍스트** — 배경은 흰색과 아주 옅은 회색만. 컬러는 액션과 상태에만 씁니다.
2. **AI가 쓴 글은 티가 나야 합니다** — 원문 발췌와 LLM 요약문을 시각적으로 구분합니다. 사용자가 "이건 기계가 쓴 문장"임을 알 수 있어야 합니다.
3. **고정 영역을 최소화** — 상단에 붙박이로 두는 요소가 많을수록 모바일에서 읽을 공간이 사라집니다.
4. **밀도보다 스캔 속도** — 한 화면에 많이 넣기보다, 눈이 헤드라인을 빠르게 훑도록 여백을 씁니다.

### 컬러 금지 사항

- **액센트 색을 늘리지 마세요.** 시안 하나로 버팁니다.
- **빨강·초록을 브랜드/장식 용도로 쓰지 마세요.** 상태 신호로 예약돼 있습니다.

- **드롭섀도우 금지.** 카드 구분은 `border` 1px으로만 합니다.
- 프로바이더 색은 차트에서 **점선/실선 패턴을 함께** 써서 색맹 사용자도 구분되게 하세요.

### 다크모드

다크모드는 **2차 작업**입니다. 먼저 라이트모드를 완성하세요. 다크모드 진행 시 액센트는 `#155E75` → `#22D3EE` (cyan-400)로 교체합니다. `#155E75`는 어두운 배경에서 보이지 않습니다.

## 3. 타이포그래피 `[제안]`

**서체**: Pretendard (한글·영문 통합). Figma에 없으면 `Noto Sans KR`로 대체.
숫자가 많은 관리자 화면의 표·차트 축 라벨은 `tabular-nums` 설정을 켜서 자릿수를 정렬하세요.

| 역할 | 크기 | 굵기 | 자간 | 용도 |
|---|---|---|---|---|
| Display | 28px | 600 | -0.02em | 페이지 타이틀 (`/` 최상단 등) |
| H1 | 22px | 600 | -0.01em | 섹션 헤딩 |
| H2 | 18px | 600 | -0.01em | 카드 그룹 헤딩 |
| Headline | 16px | 600 | -0.01em | 기사 카드 제목 |
| Body | 15px | 400 | 0 | AI 요약 본문 |
| Caption | 13px | 400 | 0 | 출처, 시간, 보조 |
| Micro | 12px | 500 | 0 | 뱃지, 칩 라벨 |

**행간**: 헤드라인 1.4, 본문 1.6, 뱃지 1.0

**금지**: 12px 미만 사용 금지. 굵기는 400/500/600 세 가지만.

## 4. 간격·모서리 `[제안]`

- **간격 스케일**: 4 / 8 / 12 / 16 / 24 / 32 / 48px — 이 값만 쓰세요.
- **모서리**: 카드 12px, 버튼·입력 8px, 뱃지·칩 6px, 아바타 원형.
- **테두리**: 1px `#E2E8F0`. 강조가 필요하면 색을 바꾸지 말고 두께를 2px로.
- **카드 내부 여백**: 데스크톱 16px 20px, 모바일 14px 16px.

## 5. 레이아웃 `[확정]`

### 데스크톱 (1440px 기준)

- **본문 컬럼 폭 760px, 중앙 정렬.** 화면이 넓어도 컬럼을 늘리지 마세요. 텍스트 한 줄이 길어지면 읽기가 나빠집니다.
- 좌측에 **아이콘 네비게이션 레일** (폭 64px, 접힌 상태). 항목: 뉴스 / 설정 / (관리자만) 관리.
- 상단 헤더에 로고 + 검색 아이콘 + 프로필 아이콘.
- 양옆 나머지는 여백. 무언가로 채우지 마세요.

### 모바일 (375px 기준)

- **하단 탭바를 만들지 마세요.** 이동할 화면이 뉴스·설정 둘뿐이라 탭바를 둘 이유가 없습니다.
- 상단 헤더 한 줄로 처리: 좌측 로고, 우측에 검색 아이콘 + 프로필 아이콘 (프로필 → 설정·관리자 진입).
- 헤더 높이 56px.
- 좌우 여백 16px.

### 고정(sticky) 영역 규칙 — 중요

**상단 고정 영역은 최대 2단, 합계 높이 120px를 넘지 마세요.**

레퍼런스로 본 서비스가 검색창 + 트렌드 + 탭 + 칩을 모두 고정해 215px를 상시 점유했고, 모바일에서 실제 기사가 보이는 영역이 절반 이하로 줄었습니다. 같은 실수를 반복하지 마세요.

- 고정: 페이지 헤더 1단 + 필터 1단
- 고정 아님: 그 외 모든 것

## 6. 핵심 컴포넌트

### 6.1 기사 목록 행 (피드용) — 가장 중요

#### 형태: 개별 카드가 아니라 "구분선 목록"

떠 있는 카드를 나열하지 마세요. **하나의 흰 컨테이너 안에 행이 쌓이고, 행 사이를 1px `#E2E8F0` 구분선으로 나눕니다.**

- 컨테이너: 흰 배경, 모서리 12px, 1px `#E2E8F0` 테두리
- 행: 배경 투명, 모서리 없음, 좌우 여백 20px (모바일 16px)
- 행 사이 구분선은 좌우 여백 안쪽까지만 (컨테이너 끝까지 긋지 않음)
- 마지막 행 아래에는 구분선 없음

목록이 붙어 있어야 눈이 헤드라인을 세로로 빠르게 훑습니다. 카드가 하나씩 떠 있으면 시선이 매번 끊깁니다.

#### 행 구성 (위에서 아래로)

1. **메타 행** (높이 20px)
   - 좌측: 출처 뱃지 — `#F1F5F9` 배경 + `#334155` 글자, 12px, 좌우 여백 8px, 모서리 6px
   - 뱃지 우측에 가운뎃점으로 구분한 보조 정보 (`· 속보`, `· IT`) — 12px `#64748B`
   - 우측 끝: 상대 시간 (`12분 전`) — 12px `#64748B`
2. **헤드라인** — 16px/600 `#0F172A`, **최대 2줄**, 넘치면 말줄임
3. **태그 행** (높이 24px) — 매칭된 관심 태그 칩 최대 2개, `#CFFAFE` 배경 + `#155E75` 글자, 12px

**요약문은 목록에 넣지 않습니다.** 행을 누르면 상세 화면으로 이동해 거기서 요약을 봅니다.

**행 높이 목표: 100~120px.** 여기서 더 늘리지 마세요.

**썸네일 이미지는 넣지 않습니다.** 텍스트만으로 구성합니다.

#### 상태

| 상태 | 표현 |
|---|---|
| 기본 | 위 구성 그대로 |
| hover | 행 배경 `#F8FAFC`, 커서 pointer |
| 읽음 | 헤드라인 `#64748B` |
| 신규 | 출처 뱃지 왼쪽에 앰버 `#F59E0B` 점 6px |

### 6.2 AI 요약 블록 (상세 화면 전용) — 시그니처 요소

이 서비스에서 AI가 드러나는 유일한 자리입니다.

- 좌측에 2px 세로선 `#155E75`, 그 오른쪽 12px 지점부터 요약문
- 세로선이 붙은 쪽은 모서리 라운드 없음 (0px)
- 요약문 15px/400 `#334155`, 행간 1.6, 3줄
- 블록 위에 `AI 요약` 라벨 — `#CFFAFE` 배경 + `#155E75` 글자, 12px
- **원문 발췌에는 절대 쓰지 마세요.** 이 세로선은 "기계가 쓴 문장"이라는 신호입니다.

### 6.3 기사 상세 모달 — 목록 위에 띄웁니다

별도 페이지가 아니라 **목록 위에 겹치는 모달**입니다. 목록의 스크롤 위치는 유지되고, 닫으면 보던 자리로 돌아옵니다.

#### 데스크톱

- 오버레이: `#0F172A` 50% 투명도, 화면 전체
- 모달: 폭 640px, 중앙 정렬, 상하 여백 최소 48px, 최대 높이 화면의 80%
- 배경 흰색, 모서리 12px, 내부 여백 32px
- 우상단에 닫기 버튼 (24px, `#64748B`)
- 내용이 길면 모달 안에서만 스크롤. 뒤 목록은 스크롤되지 않습니다.

#### 모바일

- **바텀 시트**로 올라옵니다. 화면 하단에서 위로 슬라이드.
- 폭 100%, 상단 모서리만 16px, 최대 높이 화면의 90%
- 상단 중앙에 드래그 핸들 (폭 36px, 높이 4px, `#CBD5E1`)
- 아래로 끌어내리면 닫힘
- 내부 여백 20px

#### 내용 구성

1. 메타 행 — 출처 뱃지 + 상대 시간
2. 헤드라인 — 20px/600 `#0F172A`
3. **AI 요약 블록** (6.2) — 3줄
4. 하단 액션 행 — `원문 보기` Primary 버튼 (새 탭으로 열림을 아이콘으로 표시)

번역, 관련 기사, 공유, 스크랩은 넣지 않습니다.

#### 이전/다음 이동

모달 좌우(모바일은 하단)에 **이전 기사 / 다음 기사** 버튼을 둡니다.
상세가 단순하기 때문에, 모달을 닫지 않고 기사를 연속으로 훑을 수 있는 게 이 방식의 가장 큰 장점입니다. 목록 첫 기사에서는 이전 버튼, 마지막에서는 다음 버튼을 비활성으로.

#### 반드시 지켜야 할 동작

- 열릴 때 **포커스가 모달 안으로 이동**하고, 모달 밖으로 탭 이동이 나가지 않습니다
- `ESC` 키로 닫힘, 오버레이 클릭으로 닫힘
- 닫으면 **원래 눌렀던 목록 행으로 포커스가 돌아갑니다**
- 열려 있는 동안 뒤 목록의 스크롤을 잠급니다
- URL은 `/articles/:id`로 바뀝니다. 그 주소로 직접 들어오면 목록 위에 모달이 열린 상태로 보입니다. 링크 공유와 뒤로가기가 정상 동작해야 합니다

#### 상태

로딩(스켈레톤 3줄), 오류(문구 + `다시 시도` 버튼) 두 가지를 함께 그려주세요.

### 6.4 버튼

| 종류 | 배경 | 글자 | 테두리 |
|---|---|---|---|
| Primary | `#155E75` | `#FFFFFF` | 없음 |
| Secondary | `#FFFFFF` | `#0F172A` | 1px `#E2E8F0` |
| Ghost | 투명 | `#155E75` | 없음 |
| Danger | `#FFFFFF` | `#991B1B` | 1px `#FECACA` |

높이: 기본 40px, 소형 32px. 좌우 여백 16px.
**한 화면에 Primary 버튼은 하나만.**

### 6.5 필터 칩

높이 32px, 모서리 6px. 선택 시 `#0F172A` 배경 + 흰 글자. 미선택 시 `#FFFFFF` 배경 + `#334155` 글자 + 1px 테두리.

### 6.6 상태 화면 — 반드시 함께 디자인하세요

각 목록 화면마다 4가지 상태가 필요합니다. 기본 상태만 만들고 끝내지 마세요.

- **로딩**: 스켈레톤. 스피너 대신 카드 형태의 회색 블록 3개.
- **비어 있음**: 안내 문구 + 행동 유도 버튼. "데이터가 없습니다"만 쓰지 마세요. 예: "아직 관심 태그가 없어요" + `태그 고르기` 버튼.
- **오류**: 무엇이 잘못됐고 무엇을 하면 되는지. + `다시 시도` 버튼.
- **끝 도달**: 무한 스크롤 마지막에 "더 이상 기사가 없습니다".

### 화면별 메모

**`/`** — 전체 작업량의 30%. 여기에 가장 공을 들이세요.
구조: 페이지 헤더 → 필터 칩 행 → 기사 목록 무한 스크롤. 추천 섹션은 만들지 않습니다.

**로그인 상태에 따라 같은 화면이 두 가지로 동작합니다. 두 버전을 모두 그려주세요.**

| | 비로그인 | 로그인 |
|---|---|---|
| 페이지 헤딩 | `최신 뉴스` | `관심사 기반 뉴스` |
| 필터 칩 행 | 카테고리 칩 (IT / 경제 / 정치 …) | 사용자의 관심 태그 칩 + 맨 앞에 `전체` 칩 |
| 기본 선택 | `전체` | `전체` (= 내 관심 태그 전부) |
| 목록 내용 | 최신순 전체 기사 | 관심 태그에 걸린 기사 |
| 행의 태그 칩 | 표시하지 않음 | 매칭된 태그 최대 2개 표시 |
| 상단 배너 | `로그인하고 관심사에 맞는 뉴스 받기` + 로그인 버튼 | 없음 |

비로그인 배너는 목록 위 1회만. 스크롤 중간에 끼워 넣지 마세요.

**`/admin/llm-usage`** — 상단에 요약 숫자 카드 4개 (총 호출 수 / 총 토큰 / 예상 비용 / 실패율), 아래 차트 3종 (프로바이더별 비용 추이 / 모델별 호출 분포 / 일별 토큰 사용량).
토큰 수를 제공하지 않는 프로바이더가 있어 일부 값은 추정치입니다. **"추정" 라벨을 표시할 자리를 반드시 만드세요.**

**`/admin/pipeline`** — 배치 실행 목록. 각 행에 실행 시각, 단계별 진행 상태, 처리 건수, 상태 뱃지.
**오류 상세는 별도 페이지로 만들지 말고 우측 사이드 드로어(폭 480px)로 여세요.** 목록과 상세를 자주 오가야 해서 페이지 전환은 답답합니다.

## 9. 아직 정해지지 않은 것

임의로 결정하지 말고 **비워두거나 대안 2개를 만들어** 주세요.

- 로고·서비스명 (미정)
- 다크모드 전체 화면
- 온보딩 플로우의 태그 선택 UI 형태 (칩 다중선택 vs 카테고리 아코디언)
- **검색 화면 (`/search`)** — 헤더에 검색 아이콘은 두지만, 검색은 담당 기능 7개에 포함돼 있지 않습니다. 아이콘만 배치하고 화면은 그리지 마세요.
- **번역 UI** — 담당자 부재로 보류. 나중에 살아나면 상세 화면의 요약 블록 위에 언어 선택을 추가하는 자리를 비워두세요.
- 사용자가 자유 키워드를 입력할 수 있는지 여부 (백엔드 확인 대기 중)
- 비로그인 상태에서 피드 접근 허용 여부 (백엔드 확인 대기 중)
